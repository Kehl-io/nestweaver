## Bounded nw852 measurement

The frozen corpus has 4000 JavaScript modules with eight functions each and an index module that calls the last function in 40 modules. Functional churn changes a constant in the first 400 files; comment churn prepends one line to the first 284 files, shifting their symbol coordinates. SHA comparisons confirm those content-change counts. Applying either variant rewrites **all 4001 files' mtimes**, so this qualifies hash-level skipping, not the untouched-file mtime fast path.

The standard CLI without `--force` uses tiered file metadata, dependency expansion and per-file writes in the common indexing funnel; it is not the separate Git-diff `incremental_index_with_reader` API. `--force` treats old file metadata as absent for scan/replacement and bypasses selective resolution planning, but parsed/resolution caches remain available. These are **not cold/no-cache trials**. Raw `incremental`/`full` mode labels and commands were retained unchanged. Each measured trial follows the same unmeasured forced preparation of the base corpus; setup and oracle reads are excluded from measured index wall time.
